# ADR 0034: what 1.0 promises

Status: accepted (2026-11-16, the owner). Plan reference: M7 L12, task W5.

## Decision

From the 1.0.0 tag, `docs/stability.md` states what every 1.x release keeps.

- **Kept across 1.x:**
  - `config.toml` keys. A key that is replaced is still parsed and warned about for the rest of
    1.x.
  - The admin REST API under `/api`. Fields may be added, never removed or renamed. There is no
    new `/api/v1` prefix: the promise covers `/api` as it is.
  - The CLI's commands, flags and exit codes (0 success, 1 the proxy refused or a check failed,
    2 usage or connection errors).
  - Metric names and labels.
  - The access log line format.
  - Every database written by a 1.x release opening in any later 1.x release, through the
    migrations of ADR 0028.
- **Not promised:**
  - the UI's look and layout;
  - the text of log messages;
  - `/api` endpoints marked experimental in the API reference.
- **Until 1.0.0 is tagged,** AGENTS.md keeps "no compatibility work" for config, API and
  behavior. The database is the exception, already migrated under ADR 0028. At the tag,
  AGENTS.md's "Compatibility and migration" section is replaced with these rules.

## Consequences

The configuration and API references (M7 W2, W3) are the list the promise refers to. Their tests
make an undocumented key or route fail CI, so nothing reaches 1.0 by accident. A breaking change
after 1.0 waits for 2.0.
